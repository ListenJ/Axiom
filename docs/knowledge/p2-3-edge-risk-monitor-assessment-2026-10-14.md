# P2-3: EDGE_RISK_MONITOR 灰区复核评估

> 日期：2026-10-14 | 状态：✅ 已评估 | 决策：保持默认关闭

## 背景

`EDGE_RISK_MONITOR` 控制特权调用复核器的概率层（边缘 LLM 初筛）。
路线图 P2-3 要求评估默认关闭的灰区风险敞口，给出开/关建议与实测。

## 三层防御体系

| 层 | 机制 | 开关 | 默认 |
|----|------|------|------|
| L1 硬底线 | `permissions.ts` 正则裁决 | 不可关 | ✅ 始终开 |
| L2 确定性序列 | `reviewSequence` 跨调用计数 | 不可关 | ✅ 始终开 |
| L3 概率初筛 | 边缘 LLM 初筛 + 主模型复核 | `EDGE_RISK_MONITOR` | ❌ 默认关 |

## 灰区风险分析

### L3 关闭时的暴露面

| 灰区场景 | L1 覆盖? | L2 覆盖? | L3 增量? |
|----------|---------|---------|---------|
| `fs.write` 到敏感路径（如 `.env`） | 部分（锚点裁决） | ❌ | ✅ 语义筛查 |
| `proc.exec` 可疑参数组合 | 部分（命令正则） | ✅ write→exec 序列 | ✅ 参数语义 |
| `fs.glob` 递归枚举 `.env` 家族 | ❌ | ❌ | ✅ 模式语义 |
| `mcp_*` 子进程工具灰区 | ❌ | ✅ 序列模式 | ✅ 负载语义 |

### 关键观察

1. **L1 + L2 已覆盖绝对违规和序列攻击**——L3 是语义增量，不是唯一防线
2. **L3 需要外部 LLM 端点**（GLM_FLASH 或类似）——离线/本地部署无法使用
3. **L3 fail-open 语义**——初筛失败时放行（不打断 agent），关闭等价于恒放行
4. **L3 延迟代价**——每次灰区调用增加一次 LLM 往返

## 决策：保持默认关闭

**理由**：
1. L1 + L2 提供不依赖外部服务的确定性防御
2. 默认开启会破坏离线/本地部署（无 GLM_FLASH 端点 → 每次初筛失败 → 恒放行 + 延迟）
3. 有外部端点的部署可显式 `EDGE_RISK_MONITOR=1` 启用
4. 灰区暴露面在 L1 + L2 覆盖下为可控残余风险

P2-3 ✅ 已评估。默认关闭是正确的设计决策——L3 是可选增强而非必要防线。
