# P2-5: 测试并行化评估

> 日期：2026-10-14 | 状态：✅ 已评估 | 决策：当前不并行化

## 背景

路线图 P2-5 要求评估测试并行化可行性。F7 审计发现跨文件单例/桩污染真实存在。
当前串行测试套件 4673 tests / ~26s。

## 实测

| 模式 | 结果 | 耗时 |
|------|------|------|
| 串行（当前） | 4673 pass / 0 fail / 67 skip | ~26s |
| `--parallel=2` | 3737 pass / **98 fail** | — |

### 失败分布

98 failures 集中在前端组件测试：
- `ApprovalModal.test.tsx`（6 fail）
- `BarChart.test.tsx`（1 fail）
- 其他前端组件（DOM/mock 状态跨文件污染）

### 根因

前端组件测试共享 DOM 全局状态和 mock 桩。并行 worker 各自有独立 module registry，
但 `bunfig.toml` 的 `dom = true` 使 jsdom 全局注入在 worker 间产生竞争。

## 决策：当前不并行化

**理由**：
1. **26s 已经很快**——并行化的边际收益小（可能 15s vs 26s）
2. **98 failures 证明 F7 污染是真实的**——不是假阳性
3. **修复成本高**——需要为每个测试目录建立隔离边界（独立 worker + 无共享状态）
4. **门禁语义不动**——路线图明确要求"不动门禁语义"

## 未来路径（如果需要）

1. 按目录分片：`tests/frontend/` 用独立 worker，`tests/src/` 用另一个
2. `--no-isolate` + 按目录分组：让每个 worker 只跑一个目录
3. 前端测试改用 Vitest（自带 jsdom 隔离）
4. 但这些都需要大量测试重构工作，当前 ROI 不足

## 结论

P2-5 ✅ 已评估。26s 串行是当前最优策略。并行化在 F7 污染修复前不可行。
