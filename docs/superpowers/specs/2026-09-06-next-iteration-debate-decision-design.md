- **演进战略派**：TOP = ①宿主接入≥3 + 分发（值5/成4/险3）②收口+沙箱标定（值3/成1/险1）③EarlyEval+执行错误治理（值3/成2/险2）。Q2 投"C > A > EarlyEval"；flaky 押后顺手修。最大浪费点："给零外部消费者的运行时继续加评测精度——测量精度在涨，外部有效性仍是零验证"。

## 3. 裁决与理由

- **D1/D2 按 3:0 直接通过**：D1 是规则 3/5 的合规要求（所有修改必须留痕提交），且改动已验证绿，"保留观察"只会增加 rebase 腐化与留痕债。D2 兑现上轮辩论 D3 承诺，gate 与落地形态均已就绪，设计成本已付，只剩 TDD 施工。
- **D3 次序裁定（2:1 折中）**：A 排第一（3:0）。执行错误治理（结论#3 点名）插在 FTS 前——参数级改动先行止损，让后续每轮评测更便宜。宿主接入采纳**单宿主切片**（OpenCode）：演进派的复利论点成立（审计证实宿主接入走 MCP 面、与 R-024 PTY 无关，稳定派反对依据不成立），但 ≥3 宿主 + 分发线在单宿主冒烟给出第一手信息前不扩面——既回应精益派"成本不可预测"的顾虑，又买进"外部宿主能否消费 189 工具面"的关键信息。
- **D4 EarlyEval 押后一轮**：数字属实、方向正确，但执行错误治理先行（更轻、直接压 zhipu 1→14 / sensenova 9→19 的易损点）；治理后若执行错误率仍高，EarlyEval 升为下迭代第一候选。
- **D5 flaky 最小核实**：llm-cache 是 7 项中唯一的"存量失败"类（非时序抖动），核实成本极低且是真缺陷嫌疑；其余 6 项已隔离、无当前阻塞（精益/演进 2:1），维持账本并约定"触碰对应模块时顺手修"，拒绝静默续期。
- **D6 押后全部有一句话证据**（见摘要表）。轨迹轨的关键反对不是价值（2026 对标方向属实）而是时序：执行错误率未稳 + 现有断言可能部分重写，先花的结构化成本会被重写吃掉（精益派洞察）。
- **局部最优 × 整体适应**：本决策集的横纵结构——纵向把评测-进化闭环打磨到可自证（收口+标定+治理，局部性能）；横向开启第一个外部反馈源（宿主切片）与补上知识检索能力鸿沟（FTS），使后续所有迭代多一个真实校准维度（整体适应性）。
