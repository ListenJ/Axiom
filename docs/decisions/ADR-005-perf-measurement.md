# ADR-005：渲染性能达标线的测量口径

- 日期：2026-09-11 ｜ 状态：**已采纳** ｜ 决策人：项目经理（用户）
- 背景：T3.3 验收"目标页面交互帧率/提交耗时提升 ≥30%"，需统一测量口径，否则"提升"不可比。候选：React Profiler 提交耗时 vs Web Vitals（INP/LCP）。

## 决定
**Profiler 提交耗时为主验收口径，Web Vitals 并报为参考**：
- 验收判定以 **T3.2 React Profiler 火焰图为基线、T3.3 优化后同场景同脚本同口径对比**为准（前后差异 ≥30% 达标）；
- Web Vitals（INP/LCP）在报告并列呈现，仅作用户体验参考，**不作门禁判定**；
- 触发路径脚本化（可复现的交互序列），测量环境固定（同机、无并发负载、冷启动一致）。

## 理由
- Profiler 提交耗时在本地 E2E 下确定性强、噪声低，能稳定支撑"≥30%"这类阈值判定；
- Web Vitals 依赖真实浏览器调度与网络，本地噪声大——flaky 账本战役（墙钟 p95 在负载下膨胀 >2x）刚验证过这类教训：不可稳定复现的指标不能进门禁。

## 备选与否决理由
- 仅 Web Vitals：本地环境无法稳定测出 30% 差异，否决。
- 仅 Profiler：脱离用户感知，作为唯一对外指标说服力弱，故保留 Vitals 并报。

## 后果与回退条件
- 后果：Profiler 口径可能放过"提交快但体感卡"的场景，由 Vitals 并报兜底人工判断。
- 回退：若上线后真实用户 INP 与 Profiler 结论矛盾（体感未改善），升级为 Vitals 主导并重定基线，追加本 ADR 记录。
