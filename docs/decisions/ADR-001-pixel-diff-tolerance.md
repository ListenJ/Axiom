# ADR-001：像素 diff 容差策略

- 日期：2026-09-11 ｜ 状态：**已采纳** ｜ 决策人：项目经理（用户）
- 背景：前端 UX 完成计划（2026-09-09）T1.3 要建确定性像素 diff 门禁。0px 严格与抗锯齿容差二选一；风险表将"基线噪声→门禁失信"列为高风险。

## 决定
采用**抗锯齿容差起步**：Playwright `toHaveScreenshot` 以 `threshold: 0.2`（像素色差容忍）+ `maxDiffPixelRatio: 0.002`（允许差异面积 0.2%）起步；动态区域（时间戳/动画/随机数据）用显式 mask 清单，允许差异必须逐条登记，禁止静默放宽。首轮基线运行两周统计误报率后再决定收紧或放宽，参数调整走 ADR 追加记录。

## 理由
- 跨环境字体渲染/抗锯齿差异使 0px 严格必然高频误报；flaky 账本战役（2026-09-10/11，7 项清零）刚证明"不可信门禁 = 没有门禁"，同一教训不重犯。
- 容差漏掉的"细微回归"由存量 LLM 视觉审核链（语义级）互补覆盖。

## 备选与否决理由
- 0px 严格：误报率不可控，门禁失信成本 > 漏检成本，否决。
- 纯 LLM 审核不建像素 diff：无确定性可复现回归证据，否决。

## 后果与回退条件
- 后果：门禁初期可能放过 <0.2% 面积的真实回归；两周校准期结束前不得声称门禁完备。
- 回退：若两周误报率仍 >5%，收紧参数；若出现容差掩盖的真实回归事故，回 0px + 全量 mask 显式化。
